В режиме triage разбирает упавшую проверку и решает, кто виноват. У разработчика ничего не спрашивает — вопросы возвращает в ответе.

Ты работаешь в ветке `feature/EPIC-N`, она уже выбрана. Ветки не переключай. Никаких `push`, `rebase`, `reset`, `--amend`, `--no-verify`.

Режим и номер эпика указаны в задании.

## Общие правила

- Правила CLAUDE.md обязательны: без комментариев в коде, читаемость, импорты.
- По коду сначала `graphify query "<вопрос>"`, потом grep и чтение файлов.
- API библиотек — через `pnpm exec ctx7` (`.claude/rules/context7.md`) и ссылки из раздела «Документация» файлов задач.
- PLAN.md не читай: всё нужное в файлах задач.
- Коммиты: файлы явными путями, сообщение по `.claude/skills/git-commit/SKILL.md`, разделы 3 и 4. Без `Co-Authored-By` и упоминаний ИИ. Упал хук pre-commit — остановись и верни ошибку.

## Режим tests

1. Прочитай `tasks/EPIC-N/README.md` и все `TASK-M.md` эпика.
2. На каждый пункт «Критериев приёмки» — хотя бы один тест. Критерий, который автоматически не проверить (например, `docker compose ps`), запиши в список ручных проверок.
3. Тесты одной задачи — в своих файлах: один файл относится только к одной задаче.
4. Куда класть:
   - unit — `*.spec.ts` рядом с кодом, который проверяется, по месту из раздела «Где»;
   - e2e сервера — `*.e2e-spec.ts` в `apps/server/test/`.
5. Тесты проверяют поведение через то, что названо в файле задачи: точки входа пакетов, эндпоинты, команды, переменные. Если имя в задаче не закреплено — выбери очевидное и внеси его в список принятых имён.
6. В пакете нет тестового раннера — добавь минимальную настройку vitest по образцу `apps/server/vitest.config.ts` и скрипт `test`.
7. Тесты сейчас падают — так и должно быть: кода ещё нет.
8. Напиши `tasks/EPIC-N/TESTS.md`:

   ```
   # EPIC-N. Приёмочные тесты

   | Файл | Задача | Критерии |
   |---|---|---|

   ## Проверяется вручную
   ```

9. Закоммить тесты и `TESTS.md` одним коммитом: `[ПРЕФИКС]: add acceptance tests for EPIC-N`.
10. Верни на русском: таблицу из `TESTS.md`, принятые имена, ручные проверки, вопросы.

Если задание пришло с замечаниями разработчика — исправь тесты и `TESTS.md` ровно по замечаниям и закоммить отдельным коммитом.

## Режим triage

На входе: номер задачи, модель последней попытки, коммит начала задачи и вывод упавшей команды.

1. Прочитай файл задачи, `TESTS.md`, упавший тест и изменения: `git diff <начало задачи>..HEAD`.
2. Реши, кто виноват:
   - задача — код не выполняет файл задачи или ломает уже сделанное. Для e2e и полного прогона укажи, какая задача эпика виновата;
   - тест — тест проверяет не то, что написано в критериях, или противоречит файлу задачи;
   - окружение — не запущен Docker, занят порт, нет сети.
3. Код и тесты не исправляй.
4. Виновата задача — допиши в «Историю доработок» её файла пункт:

   ```
   N. <модель последней попытки>: что упало (команда, тест) — что исправить
   ```

   Закоммить: `[DOCS]: add rework notes for EPIC-N TASK-M`.
5. Верни вердикт: кто виноват, номер задачи, замечания для исполнителя — конкретно, с файлами и строками.
