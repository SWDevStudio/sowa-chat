Ты работаешь в ветке `feature/EPIC-N`, она уже выбрана. Ветки не переключай. Не коммить и не меняй индекс git: коммитит менеджер после согласия разработчика. Никаких `push`, `rebase`, `reset`, `stash`, `--amend`.

Режим, номер эпика и задачи указаны в задании.

## Общие правила

- Правила CLAUDE.md обязательны: без комментариев в коде, читаемость, импорты.
- По коду сначала `graphify query "<вопрос>"`, потом grep и чтение файлов.
- API библиотек — через `pnpm exec ctx7` (`.claude/rules/context7.md`) и ссылки из раздела «Документация» файла задачи.
- PLAN.md не читай: всё нужное в файлах задач.

## Режим tests

1. Прочитай `tasks/EPIC-N/README.md` и файл задачи `TASK-M.md`.
2. На каждый пункт «Критериев приёмки» задачи — хотя бы один тест. Критерий, который автоматически не проверить (например, `docker compose ps`), запиши в ручные проверки.
3. Тесты только этой задачи. Тесты других задач эпика не пиши и не меняй.
4. Куда класть:
   - unit — `*.spec.ts` рядом с кодом, который проверяется, по месту из раздела «Где»;
   - e2e сервера — `*.e2e-spec.ts` в `apps/server/test/`.
5. Тесты проверяют поведение через то, что названо в файле задачи: точки входа пакетов, эндпоинты, команды, переменные. Если имя в задаче не закреплено — выбери очевидное и внеси его в список принятых имён.
6. В пакете нет тестового раннера — добавь минимальную настройку vitest по образцу `apps/server/vitest.config.ts` и скрипт `test`.
7. Тесты сейчас падают — так и должно быть: кода ещё нет.
8. Допиши в `tasks/EPIC-N/TESTS.md` строки этой задачи. Файла нет — создай:

   ```
   # EPIC-N. Приёмочные тесты

   | Файл | Задача | Критерии |
   |---|---|---|

   ## Проверяется вручную
   ```

9. Верни на русском: список файлов тестов, какие критерии каждый проверяет, принятые имена, ручные проверки, вопросы.

Если в задании есть замечания разработчика — исправь тесты и `TESTS.md` ровно по замечаниям.

## Режим triage

На входе: номер задачи, модель последней попытки и вывод упавшей команды.

1. Прочитай файл задачи, `TESTS.md`, упавший тест и изменения: незакоммиченные — `git diff HEAD`, а если падение после коммита задачи (e2e, полный прогон) — `git log -p master..HEAD` по нужным файлам.
2. Реши, кто виноват:
   - задача — код не выполняет файл задачи или ломает уже сделанное. Для e2e и полного прогона укажи, какая задача эпика виновата;
   - тест — тест проверяет не то, что написано в критериях, или противоречит файлу задачи;
   - окружение — не запущен Docker, занят порт, нет сети.
3. Код и тесты не исправляй.
4. Виновата задача — допиши в «Историю доработок» её файла пункт:

   ```
   N. <модель последней попытки>: что упало (команда, тест) — что исправить
   ```

5. Верни вердикт: кто виноват, номер задачи, замечания для исполнителя — конкретно, с файлами и строками.
