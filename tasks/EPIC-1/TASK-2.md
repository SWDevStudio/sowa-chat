# EPIC-1 / TASK-2. Настроить сборку пакетов через tsdown

Исполнитель: sonnet
Зависит от: TASK-1
Ветка: feature/EPIC-1

## Что сделать

Настроить сборку четырёх пакетов (`protocol`, `sdk`, `bot-sdk`, `server-sdk`) через tsdown: `pnpm build` в корне собирает их в `dist/` в форматах ESM и CJS с файлами типов.

1. В каждом пакете создать `tsdown.config.ts` с точками входа из `exports` его `package.json`. У `sdk` их три: `.`, `./visitor`, `./operator`.
2. Добавить скрипт `build` в каждый пакет.
3. Проверить, что turbo собирает пакеты в правильном порядке: `protocol` раньше тех, кто от него зависит (в `turbo.json` уже стоит `dependsOn: ["^build"]`).

## Где

- `packages/*/tsdown.config.ts` — новые.
- `packages/*/package.json` — скрипт `build`.
- `turbo.json` — только если без правки не работает.

## Требования из плана

- Сборка пакетов: tsdown, на выходе ESM + CJS + d.ts.
- В монорепо сервер и пакеты берут `protocol` из исходников, а не из опубликованной версии: если формат события поменяли и забыли обновить сервер или SDK, TypeScript показывает ошибку при сборке. Поэтому `exports` в `package.json` по-прежнему указывают на `./src/...`.
- Публикация (`publishConfig`, `exports` на `dist`) настраивается в эпике релиза. Сейчас нужна только работающая сборка.
- `zod` — peerDependency пакета `protocol` и в его бандл не попадает.
- Код оператора не попадает в бандл `@sowa-chat/sdk/visitor`: точки входа `visitor` и `operator` собираются раздельно.

## Критерии приёмки

- `pnpm build` в корне проходит, в каждом пакете появляется `dist/` с `.js`, `.cjs` и `.d.ts` для каждой точки входа.
- `zod` в собранном `protocol` подключается через `import` / `require`, а не встроен в бандл.
- Повторный `pnpm build` без изменений берётся из кэша turbo.

## Чего не делать

- Не менять `exports` на `dist` и не добавлять `publishConfig`.
- Не трогать сборку `apps/server` (`nest build`).
