# EPIC-1 / TASK-5. Начальный набор кодов ошибок

Исполнитель: haiku
Зависит от: TASK-1
Ветка: feature/EPIC-1

## Что сделать

Описать в `protocol` коды ошибок API и схему тела ответа с ошибкой. Их используют фильтр ошибок на сервере и SDK, чтобы показать понятный текст.

## Где

- `packages/protocol/src/` — новый файл, например `errors.ts`.
- `packages/protocol/src/index.ts` — реэкспорт.

## Требования из плана

- Коды — строки в camelCase: camelCase везде, кроме БД.
- Начальный набор:

  | Код | Когда |
  |---|---|
  | `validationFailed` | тело, параметры или query не прошли схему (400) |
  | `unauthorized` | нет токена или ключа, либо он неверный (401) |
  | `forbidden` | нет прав на действие (403) |
  | `notFound` | объекта нет или он чужой (404) |
  | `conflict` | действие противоречит состоянию, например ответ бота после того, как диалог забрали (409) |
  | `payloadTooLarge` | тело запроса больше лимита (413) |
  | `rateLimited` | превышен лимит запросов (429) |
  | `internalError` | непредвиденная ошибка сервера (500) |
  | `contextInvalid` | context первого сообщения не прошёл лимиты; приходит событием в SDK, а не HTTP-ответом |

- Тело ответа с ошибкой: `{ statusCode, message, code, requestId, details? }`. `statusCode` — HTTP-статус числом. `message` — короткий текст для разработчика, не для посетителя. `requestId` — обязательный UUID, тот же ID, что в логах. `details` — необязательный массив, например список полей, не прошедших проверку.
- Коды — часть контракта с клиентами: внутри мажорной версии их нельзя переименовывать.

## Критерии приёмки

- Коды доступны как константы и как тип-объединение строк.
- Схема тела ошибки принимает корректное тело и отклоняет тело с неизвестным кодом.
- Тело ошибки содержит `statusCode` (число) и `requestId` (обязательный UUID); тело без них, со `statusCode` строкой или с `requestId` не в формате UUID отклоняется.
- `details` — необязательный массив элементов `{ path: string, message: string }`; элемент другой формы отклоняется.

## Чего не делать

- Не писать фильтр ошибок на сервере — это эпик обработки HTTP-запросов.
