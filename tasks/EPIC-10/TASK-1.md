## Что сделать

1. Режим `cli` запускает `nest-commander` (`CommandFactory`): `node dist/main.js cli <команда> [аргументы]`.
2. Модуль режима подключает конфиг, логи, БД и шину событий; HTTP и Redis не подключаются.
3. `--help` выводит список команд.
4. Неизвестная команда или ошибка выполнения — код выхода 1 и понятное сообщение.
5. После выполнения команды процесс завершается сам, соединения закрываются.
6. В `apps/server/package.json` добавить `bin` с именем `sowa-chat`, который запускает режим `cli`: `sowa-chat project:create …`. В Docker-образе эта команда будет в `PATH`.

## Где

- `apps/server/src/` — модуль режима `cli`.
- `apps/server/src/main.ts`, `apps/server/package.json`.

## Требования из плана

- Проекты и ключи создаются только через CLI внутри контейнера (`docker compose exec api sowa-chat …`): кто может выполнять там команды, тот и так владеет сервером, а по сети утечь нечему. Мастер-ключа нет.
- Один образ работает в режимах `api`, `worker`, `migrate` и `cli`.

## Критерии приёмки

- `node dist/main.js cli --help` выводит список команд и выходит с кодом 0.
- Неизвестная команда — код 1.
- После команды не остаётся открытых соединений с БД.
