# EPIC-10 / TASK-2. Создание проекта

Исполнитель: sonnet
Зависит от: TASK-1
Ветка: feature/EPIC-10

## Что сделать

1. Команда `project:create --name <имя> [--origin <origin> ...]`:
   - создаёт проект с уникальным именем;
   - создаёт publicKey `pk_…` и сохраняет его в `projects.public_key`;
   - выпускает serverKey `sk_…` через сервис ключей;
   - записывает разрешённые домены, если они переданы;
   - выводит `pk_` и `sk_` в терминал один раз: `sk_` больше нигде не показывается.
2. Команда `project:list` — список проектов: имя, ID, `pk_`, разрешённые домены. Без `sk_` и хешей.
3. Создание проекта — одна транзакция: если ключ не выпустился, проекта тоже нет.
4. Создание проекта публикует событие для журнала аудита (добавить в список подписчика аудита).
5. Логика создания проекта — в доменном сервисе, а команда CLI — тонкая обёртка над ним: тот же сервис позже вызовут режимы development и production.

## Где

- `apps/server/src/domain/projects/` — сервис создания проекта.
- Модуль режима `cli` — команды.

## Требования из плана

- `docker compose exec api sowa-chat project:create` выводит ключи один раз в терминал.
- В production ключи никогда не печатаются в лог; терминал при ручном запуске команды — не лог.
- Ключ показывается один раз при создании.
- Проект ищется по имени: `--project main`.

## Критерии приёмки

- `project:create --name main` выводит `pk_` и `sk_`, в БД появляется проект и ключ в виде хеша.
- Повторный `project:create --name main` — ошибка «проект уже есть», код 1.
- `project:list` показывает проект и не показывает `sk_`.
- В `audit_log` есть запись о создании проекта.

## Чего не делать

- Не создавать канал `web` и офлайн-бота — это эпики каналов и ботов.
