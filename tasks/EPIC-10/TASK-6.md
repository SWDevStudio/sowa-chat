# EPIC-10 / TASK-6. Перешифровка секретов после смены ключа

Исполнитель: sonnet
Зависит от: TASK-1
Ветка: feature/EPIC-10

## Что сделать

Команда `secrets:reencrypt` перешифровывает все зашифрованные значения в БД текущим ключом шифрования.

1. Реестр зашифрованных полей: каждое зашифрованное поле (таблица и колонка) регистрируется в одном месте. Сейчас таких полей нет. Позже свои поля зарегистрируют эпики ботов (`bots.transport_config`) и исходящих событий (`webhook_subscriptions.secret`). Команда работает по реестру и сама о таблицах не знает.
2. Перешифровываются только значения, зашифрованные не текущей версией ключа.
3. Работа идёт пачками (например, по 500 записей), каждая пачка — в своей транзакции. Если команда прервалась, повторный запуск продолжает с того, что осталось.
4. Значение, которое не расшифровывается ни одним ключом, не меняется: команда пишет его таблицу и ID и в конце завершается с кодом 1.
5. Флаг `--dry-run` только считает, сколько значений по каким версиям ключа лежит в каждом поле.
6. Результат: сколько значений перешифровано по каждому полю. Запуск пишется в журнал аудита: кто запустил (`cli`) и сколько перешифровано, без значений.
7. Порядок ротации, который команда поддерживает: добавить новый ключ в `SOWA_ENCRYPTION_KEYS` и перезапустить сервис → `secrets:reencrypt` → `--dry-run` показывает, что старой версии не осталось → убрать старый ключ из env.

## Где

- `apps/server/src/infra/crypto/` — реестр зашифрованных полей.
- Модуль режима `cli` — команда.

## Требования из плана

- Ключ шифрования: в каждой зашифрованной записи хранится версия ключа; при ротации записи перешифровывает команда CLI `secrets:reencrypt`. Ротация — редкая ручная операция, и фоновая задача для неё не нужна.
- Утекли ключ шифрования вместе с дампом БД — ротация ключа и перевыпуск секретов вебхуков.

## Критерии приёмки

- Тестовое зарегистрированное поле с записями, зашифрованными версией 1: после добавления версии 2 и `secrets:reencrypt` все записи зашифрованы версией 2 и расшифровываются в исходные значения.
- Повторный запуск ничего не меняет.
- `--dry-run` ничего не меняет в БД и показывает число записей по версиям.
- Запись, которая не расшифровывается, остаётся как была, код выхода 1.
