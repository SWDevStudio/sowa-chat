Ветка: feature/EPIC-11

## Что сделать

В development сервис стартует без ручной настройки секретов: недостающие секреты генерируются при первом старте и сохраняются, чтобы при следующем старте были теми же.

1. Механизм работает внутри модуля конфигурации: при `SOWA_ENV=development` для секрета, которого нет в env, значение берётся из файла секретов или генерируется и записывается в него.
2. Файл лежит в папке `SOWA_DEV_SECRETS_DIR` (по умолчанию `./.sowa-dev`). В docker-compose для разработки эта папка — volume. Добавить `.sowa-dev` в `.gitignore`.
3. Механизм общий: секрет регистрируется описанием «имя переменной + как сгенерировать значение». Сейчас регистрируется `SOWA_ENCRYPTION_KEYS` (ключ версии 1, 32 случайных байта). Ключ подписи токенов зарегистрирует эпик доступа бекенда и операторов.
4. Значение из env всегда важнее файла.
5. В production механизм выключен полностью: файл не читается и не создаётся.
6. Файл создаётся с правами только для владельца.

## Где

- `apps/server/src/infra/config/`.
- `.gitignore`, `apps/server/.env.example`.

## Требования из плана

| | development | production |
|---|---|---|
| Секреты (подпись JWT, ключ шифрования) | генерируются при первом старте и сохраняются в volume | обязательны в env; без них сервис не стартует и пишет, чего не хватает |

## Критерии приёмки

- Первый старт в development без `SOWA_ENCRYPTION_KEYS` создаёт файл секретов; второй старт берёт тот же ключ: значение, зашифрованное в первый раз, расшифровывается во второй.
- Если `SOWA_ENCRYPTION_KEYS` задан в env, файл для него не используется.
- В production без `SOWA_ENCRYPTION_KEYS` сервис не стартует и называет переменную, файл не создаётся.
