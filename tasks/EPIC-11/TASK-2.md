# EPIC-11 / TASK-2. Проект main и ключи при старте в development

Исполнитель: haiku
Зависит от: TASK-1
Ветка: feature/EPIC-11

## Что сделать

1. При старте режима `api` в development, если проекта `main` нет, он создаётся тем же доменным сервисом, что использует `project:create`.
2. Разрешённые домены:
   - сайта — из `SOWA_INIT_ALLOWED_ORIGINS`, если она задана, иначе `http://localhost:5173` (порт Vite по умолчанию: на нём будет демо-сайт playground);
   - админки — из `SOWA_INIT_OPERATOR_ALLOWED_ORIGINS`, если она задана, иначе `http://localhost:5174` (демо-админка playground).
3. `pk_` и `sk_` сохраняются в файл секретов development (механизм из TASK-1) и печатаются в лог при каждом старте в development, чтобы разработчик мог их найти.
4. Если проект уже есть, ничего не создаётся.
5. Несколько реплик `api`, стартующих одновременно, не создают проект дважды (advisory lock PostgreSQL или опора на уникальность имени с обработкой конфликта).

## Где

- `apps/server/src/domain/projects/` или отдельный модуль начальной настройки.
- Модуль режима `api`.

## Требования из плана

- В development проект `main` и ключи создаются автоматически при старте и печатаются в лог.
- Разрешённые домены сайта (CORS) в development — `localhost`.
- В production ключи никогда не печатаются в лог.

## Документация

- https://docs.nestjs.com/fundamentals/lifecycle-events
- https://www.postgresql.org/docs/18/explicit-locking.html#ADVISORY-LOCKS

## Критерии приёмки

- Первый старт в development на чистой БД создаёт проект `main` и печатает `pk_` и `sk_` в лог.
- Второй старт не создаёт новых записей и печатает те же ключи.
- Две реплики, стартующие одновременно, создают один проект.
- В production проект `main` автоматически не создаётся.

## Чего не делать

- Не реализовывать `SOWA_INIT_*` для production — это TASK-3.
