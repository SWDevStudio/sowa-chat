# EPIC-11 / TASK-3. Первый проект из SOWA_INIT_* в production

Исполнитель: sonnet
Зависит от: —
Ветка: feature/EPIC-11

## Что сделать

1. Переменные:
   - `SOWA_INIT_PROJECT` — имя первого проекта;
   - `SOWA_INIT_SERVER_KEY` — serverKey, заранее сгенерированный командой `key:generate`;
   - `SOWA_INIT_ALLOWED_ORIGINS` — домены сайта через запятую;
   - `SOWA_INIT_OPERATOR_ALLOWED_ORIGINS` — домены админки через запятую.
2. При старте `api` в production, если `SOWA_INIT_PROJECT` задан и такого проекта нет, — создать проект: сохранить хеш переданного ключа, сгенерировать `pk_`, записать оба списка доменов. Ключ проверяется по формату и контрольной сумме; неверный ключ — сервис не стартует.
3. Если проект уже есть — ничего не менять, даже если значения переменных другие. Если переданный ключ не совпадает ни с одним ключом проекта — предупреждение в лог без самого ключа.
4. Ключи никогда не печатаются в лог. `pk_` можно узнать командой `project:list`.
5. Одновременный старт нескольких реплик создаёт проект один раз.
6. `SOWA_INIT_SERVER_KEY` — секрет: redact в логах, в сводке при старте только «задан / не задан».

## Где

- Модуль начальной настройки из TASK-2.
- `apps/server/src/infra/config/`, `apps/server/.env.example`.

## Требования из плана

- Первый проект в production создаётся через env, удобно для Kubernetes и GitOps: DevOps генерируют ключ командой `sowa-chat key:generate` (она ничего не меняет в базе), кладут его в хранилище секретов и передают через `SOWA_INIT_PROJECT`, `SOWA_INIT_SERVER_KEY`, `SOWA_INIT_ALLOWED_ORIGINS`, `SOWA_INIT_OPERATOR_ALLOWED_ORIGINS`.
- `SOWA_INIT_*` применяются только при первом запуске: сервис создаёт проект, если его ещё нет, и сохраняет хеш ключа, а при последующих запусках ничего не меняет. Та же схема, что у `POSTGRES_PASSWORD`.
- Второй способ — вручную: `project:create`.

## Критерии приёмки

- Старт в production с `SOWA_INIT_*` на чистой БД создаёт проект; переданный ключ проходит проверку.
- Повторный старт с изменёнными `SOWA_INIT_*` ничего не меняет в БД.
- Ключ с неверной контрольной суммой — сервис не стартует.
- В логах нет ни `sk_`, ни `pk_`.
