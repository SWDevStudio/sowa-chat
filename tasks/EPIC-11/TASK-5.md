# EPIC-11 / TASK-5. Команда secrets:generate для production

Исполнитель: haiku
Зависит от: TASK-1
Ветка: feature/EPIC-11

## Что сделать

1. Команда `sowa-chat secrets:generate` печатает в stdout готовый блок переменных `ИМЯ=значение`, который DevOps копируют в хранилище секретов или `.env`.
2. Список секретов берётся из того же реестра, что генерирует секреты в development (TASK-1): «имя переменной + как сгенерировать значение». Новых списков не заводить: секрет, который зарегистрирует следующий эпик (ключ подписи токенов — EPIC-12), появится в выводе сам.
3. Дополнительно печатается `SOWA_INIT_SERVER_KEY` — новый `sk_` тем же кодом, что `key:generate`.
4. Флаг `--rotate`: команда читает текущие списки ключей из env (`SOWA_ENCRYPTION_KEYS`, позже `SOWA_TOKEN_SIGNING_KEYS`) и печатает их новые значения — старые ключи на месте, добавлен ключ следующей версии. Секреты без версий в этом режиме не печатаются.
5. Команда не подключается к БД, Redis и S3 и работает с пустым env, кроме `--rotate`.
6. Значения идут только в stdout, в лог приложения они не попадают.

## Где

- Модуль режима `cli` — команда.
- `apps/server/src/infra/config/` — реестр секретов из TASK-1.

## Требования из плана

- Секреты для production печатает команда `sowa-chat secrets:generate` готовым блоком переменных; она не обращается к БД и ничего не меняет. С флагом ротации — новый ключ следующей версии.
- Ключ шифрования: в каждой зашифрованной записи хранится версия ключа, при ротации записи перешифровывает `secrets:reencrypt`.

## Критерии приёмки

- Вывод `secrets:generate` с пустым env можно подставить как `.env` для production, и конфиг проходит проверку.
- Два запуска дают разные значения.
- `--rotate` с `SOWA_ENCRYPTION_KEYS=1:...` печатает список из ключа `1` без изменений и нового ключа `2`.
- Команда работает без доступной БД и Redis.

## Чего не делать

- Не записывать секреты в файлы и не менять БД.
- Не перешифровывать данные — это `secrets:reencrypt` из EPIC-10.
