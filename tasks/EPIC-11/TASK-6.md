# EPIC-11 / TASK-6. Проверка окружения при старте и команда doctor

Исполнитель: sonnet
Зависит от: TASK-4
Ветка: feature/EPIC-11

## Что сделать

Сервис сам проверяет окружение, чтобы ошибка DevOps была видна сообщением, а не симптомами.

1. Список проверок окружения — продолжение списка опасных настроек из TASK-4, в одном месте. Проверка описывается так: что проверить, уровень в production (остановка или предупреждение), текст «что не так и как исправить», где выполнять (при старте, в `doctor` или в обоих).
2. Проверки этой задачи:

   | Проверка | В production |
   |---|---|
   | у Redis `maxmemory-policy noeviction` (`CONFIG GET`) | остановка; если `CONFIG GET` запрещён — предупреждение «проверить не удалось» |
   | у Redis включён AOF | предупреждение |
   | PostgreSQL версии 18 и выше | остановка |
   | пользователь приложения не суперпользователь | предупреждение |
   | пользователь приложения может менять схему, `SOWA_MIGRATION_DATABASE_URL` не задана | предупреждение |

   Проверки S3 добавит эпик хранилища файлов, проверку доверенных прокси — EPIC-16.
3. При старте `api` и `worker` проверки выполняются после подключения к БД и Redis. Остановка — код 1 и сообщение со всеми найденными проблемами сразу, а не только с первой. Предупреждения — `warn` в сводке TASK-4.
4. В development проверки выполняются, но всё выводится как предупреждения и ничего не останавливает.
5. Команда `sowa-chat doctor` выполняет все проверки, включая проверки только для `doctor`, печатает отчёт и завершается: код 0 — нет остановок, код 1 — есть хотя бы одна. Её можно запускать до выкатки или в CI/CD.

## Где

- `apps/server/src/infra/` — список проверок рядом со списком опасных настроек из TASK-4.
- Модуль режима `cli` — команда `doctor`.

## Требования из плана

- Проверки идут при старте `api` и `worker`, а команда `sowa-chat doctor` выполняет их отдельно и печатает отчёт «что не так и как исправить».
- BullMQ требует в Redis `noeviction`, иначе при нехватке памяти Redis может выкинуть ключи очередей.
- Зависимости: PostgreSQL 18, Redis 7+ (`noeviction`, AOF).
- Приложение работает под пользователем PostgreSQL без прав суперпользователя. Достаточно одного пользователя; отдельный пользователь для миграций — по желанию.

## Критерии приёмки

- В production с Redis `maxmemory-policy allkeys-lru` сервис не стартует и называет настройку и как её исправить.
- Если `CONFIG GET` запрещён, сервис стартует с предупреждением.
- В development та же настройка Redis даёт только предупреждение.
- `doctor` при двух проблемах печатает обе и выходит с кодом 1; при отсутствии остановок — с кодом 0.
- Под суперпользователем PostgreSQL в production — предупреждение, сервис стартует.

## Чего не делать

- Не проверять S3 и доверенные прокси — это эпик хранилища файлов и EPIC-16.
- Не исправлять настройки за DevOps: проверка только сообщает.
