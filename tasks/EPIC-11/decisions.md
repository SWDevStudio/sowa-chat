## 29.10.2026, секреты development (TASK-1, TASK-4)

- Ключ подписи регистрирует этот эпик (решение EPIC-12 «ключ подписи в development»): запись реестра `SOWA_TOKEN_SIGNING_KEYS` + `SOWA_TOKEN_SIGNING_KEY_ID`, `kid` `dev-1`.
- Реестр — `generatedSecrets` в `apps/server/src/infra/config/generated-secrets.ts`; запись — `{ variables, generate(mode) }`. Его читают development и `secrets:generate`. Первый `kid` в production — `key-1`.
- Точка входа — `validate` у `ConfigModule.forRoot`: `loadEnv` вместо `parseEnv`. Фабрики `registerAs` читают `process.env`, поэтому сгенерированные значения и строки из файла `.env` кладутся в `process.env` до первой фабрики.
- Запись реестра «недостающая», только если все её переменные не заданы; частично заданную запись разбирает схема. Нет недостающих — файл не читается и не создаётся. В production механизм выключен.
- Файл: `<SOWA_DEV_SECRETS_DIR>/secrets.json`, по умолчанию `.sowa-dev` от рабочей папки; JSON `{ env, mainProject? }`; папка `0700`, файл `0600`. Первое создание — с флагом `wx`: из одновременно стартующих `api` и `worker` файл создаёт один, второй читает его. Перезапись — через временный файл и `rename`.
- Имя переменной `SOWA_DEV_SECRETS_DIR` — из черновика эпика и EPIC-17 TASK-3; PLAN.md его не закрепляет. Префикс `SOWA_`, UPPER_SNAKE.
- Тестовые окружения не создают файл: `.env.test` получает тестовый `SOWA_ENCRYPTION_KEYS` (ключ EPIC-9), `config.module.spec.ts` — тестовые ключи из `unit-probe.ts`. Модульные тесты сервисов шифрования и токенов без ключей создают сервисы напрямую и не меняются. Для процессов `dist/main.js` в e2e — временная `SOWA_DEV_SECRETS_DIR` (`test/support/dev-secrets-dir.setup.ts`, TASK-7).
- Volume для файла в docker-compose делает EPIC-17 TASK-3.

## 29.10.2026, начальный проект (TASK-2, TASK-7, TASK-9)

- Одновременный старт реплик — только advisory lock: `pg_advisory_xact_lock(hashtext('sowa-chat:initial-project'))` в транзакции `ProjectsService.createInitial`, затем `findByName`. Перехват `23505` не используется, `create` для CLI не меняется (решение EPIC-10).
- Готовый ключ: `IssueApiKeyInput.key?` и `CreateProjectInput.serverKey?`; неверный ключ — `InvalidApiKeyError` без текста ключа.
- Начальная настройка, сводка и проверки вызываются явно из `main.ts` (`verifyAtStartup` → `setUp` → `log` → `listen`), а не в `OnApplicationBootstrap`: `Test.createTestingModule({ imports: [ApiModule] })` в тестах на заглушках базы и Redis их не запускает, и e2e, которые сами создают `main` через CLI, не ломаются.
- Папка `apps/server/src/domain/startup/` (`StartupModule`, `InitialProjectService`, `StartupSummaryService`): старт читает проекты из `domain`, а `infra` от `domain` зависеть не может (PLAN.md, правило слоёв). По той же причине формат `SOWA_INIT_SERVER_KEY` проверяет `InitialProjectService` через `parseKey`, а не схема env.
- Development: имя всегда `main`, `SOWA_INIT_PROJECT` и `SOWA_INIT_SERVER_KEY` не читаются; домены — из `SOWA_INIT_*_ORIGINS` или `http://localhost:5173` / `http://localhost:5174`. Ключи печатаются строкой `Development project main: publicKey …, serverKey …` в тексте сообщения: поля `publicKey` и `serverKey` скрывает `redact-paths.ts`. `sk_` на повторных стартах — из `mainProject` файла секретов, если `publicKey` в файле совпадает с проектом; иначе предупреждение со ссылкой на `key:create`, новый ключ не выпускается.
- Production: ключ проверяется на каждом старте; проект есть — ничего не меняется, а если ключ не совпадает с активным `sk_` проекта (по `toLookupPrefix`), предупреждение без ключа. `SOWA_INIT_SERVER_KEY` обязателен, если задан `SOWA_INIT_PROJECT` (только production), и скрывается в логах (`redact-paths.ts`).

## 29.10.2026, проверки окружения и сводка (TASK-3, TASK-8, TASK-10, TASK-11, TASK-12, TASK-15)

- Реестр — `registeredEnvironmentChecks` и токен `environmentChecks` в `apps/server/src/infra/environment-checks/registered-environment-checks.ts`, по образцу `registeredEncryptedFields`. Проверка: `{ name, onlyInDoctor, run(context) }`, находка: `{ level: "stop" | "warn", message }`, контекст: `{ settings, dataSource, redis }`. Сюда же пишут проверки следующие эпики (S3 — эпик хранилища; EPIC-16 TASK-2 ссылается на «TASK-6» старой нумерации — теперь это TASK-3).
- Все находки собираются сразу; в development `stop` становится `warn`; ошибка проверки — `warn` `check could not run`. Предупреждения — отдельными строками `warn` перед сводкой.
- Проверки `https` и секретов из `.env.example` в development ничего не находят. Сравниваются `SOWA_S3_SECRET_KEY` с `sowa-dev-secret` и пароль `DATABASE_URL` / `SOWA_MIGRATION_DATABASE_URL` с `sowa`; значения — константы в коде (в образе нет `.env.example`), тест сверяет их с файлом. Пустые секреты и ключ шифрования уже ловит схема. Незаданный `SOWA_S3_PUBLIC_URL` в production — предупреждение.
- Пароль тестового PostgreSQL — `sowa-test`: иначе ни один старт production в e2e не прошёл бы проверку пароля из примера.
- `SOWA_PUBLIC_URL` обязательна в production для всех режимов (схема общая, как у `SOWA_ENCRYPTION_KEYS`); `SOWA_S3_PUBLIC_URL` пока необязательна.
- Суперпользователь и права на схему PostgreSQL в development не проверяются (dev compose работает под `POSTGRES_USER`); версия PostgreSQL и настройки Redis проверяются и там, предупреждением. Права на схему: `has_schema_privilege(current_user, 'public', 'CREATE')` или владение таблицами `public`.
- `doctor` создаёт клиент Redis сам (`createRedisClient`, `waitForRedis`, `closeRedis`), `RedisModule` в `cli` не подключается (решения EPIC-6, EPIC-10). Недоступный Redis — результат `redisConnection`. Отчёт — stdout, строки `уровень\tпроверка\tтекст` или `no problems found`; код 1 — через ошибку команды и `serviceErrorHandler`.
- Сводка — строки текста (`Startup summary: mode …`, `Zone …: port …` только у `api`, `Projects: N`, `Project …: allowedOrigins …, operatorAllowedOrigins …`, `Secret …: status`), не поля объекта: поле `name` скрывается. `worker` тоже показывает проекты (подключает `StartupModule`). Статусы секретов — `set`, `notSet`, `generatedForDevelopment` (camelCase, CLAUDE.md), из сырых строк `process.env` в `startupSummaryConfig`.

## 29.10.2026, secrets:generate (TASK-13, TASK-14)

- Флаг ротации — `--rotate` (PLAN.md говорит «с флагом ротации», имя не закрепляет; имя — из черновика эпика).
- Вывод без `--rotate`: записи реестра в production-варианте и `SOWA_INIT_SERVER_KEY`. С `--rotate`: оба ключа сразу, к исходному тексту добавляется новая версия; новая версия шифрования — наибольшая + 1, новый `kid` — `key-<n>`, `n` от числа ключей + 1, пока занято; `SOWA_TOKEN_SIGNING_KEY_ID` — новый `kid`. Ошибки разбора — текст схемы без значений.
- Команда не импортирует `config.module.ts`: `ConfigModule.forRoot` вызывается при импорте и при неверном env оставляет отклонённый промис, процесс упал бы. Поэтому `secrets:generate` идёт через отдельный `SecretsGenerateModule`, `CliModule` в `cli-runner.ts` и модули режимов в `main.ts` импортируются динамически. Класс команды есть и в `CliModule` — для `--help`.
