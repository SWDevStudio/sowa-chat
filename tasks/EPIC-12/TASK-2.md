# EPIC-12 / TASK-2. Guard серверного ключа для /v1/server

Исполнитель: sonnet
Зависит от: —
Ветка: feature/EPIC-12

## Что сделать

1. Guard для контроллеров `/v1/server/*`: ключ из заголовка `Authorization: Bearer sk_…` проверяется сервисом ключей (тип `server`).
2. Нет заголовка, неверный или отозванный ключ — 401 `unauthorized`.
3. После проверки ID проекта кладётся в контекст запроса (`nestjs-cls`): по нему позже работает изоляция проектов. Способ получить текущий проект из контекста — в одном месте.
4. Guard применяется ко всем контроллерам внутренней зоны с префиксом `server` (например, через общий декоратор).

## Где

- `apps/server/src/api/server/` — guard и общий декоратор.
- Место хранения контекста проекта — доступное слоям `api` и `domain` (например, `apps/server/src/infra/`).

## Требования из плана

| Кто | Чем авторизуется | Где хранится секрет | Что может |
|---|---|---|---|
| Бекенд админки | serverKey `sk_…` | только на бекенде админки | выпускать токены операторов, настраивать проект |

- Даже во внутренней зоне каждый запрос несёт ключ или токен: иначе любой скомпрометированный сервис или VPN-аккаунт получит доступ ко всей переписке.
- Авторизация только через заголовок `Authorization`; cookie для авторизации не используются.

## Критерии приёмки

- Тестовый маршрут `/v1/server/...` без ключа — 401; с верным `sk_` — 200 и в обработчике доступен ID проекта.
- Отозванный ключ — 401.
- `bk_` вместо `sk_` — 401.
