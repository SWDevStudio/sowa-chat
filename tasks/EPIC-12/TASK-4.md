# EPIC-12 / TASK-4. Guard оператора и роли

Исполнитель: sonnet
Зависит от: TASK-3
Ветка: feature/EPIC-12

## Что сделать

1. Guard для контроллеров `/v1/operator/*`: токен из `Authorization: Bearer …` проверяется сервисом токенов с `aud` `operator`. Без токена или с неверным — 401.
2. После проверки ID оператора, его роль и ID проекта кладутся в контекст запроса.
3. Декоратор ролей: маршрут, помеченный `supervisor`, недоступен роли `operator` — 403.
4. Проверка блокировки без обращения к БД: провайдер со списком заблокированных операторов в памяти реплики. Он загружается при старте и обновляется при блокировке на этой реплике. Синхронизацию между репликами добавит эпик кэша. Заблокированный оператор — 401.

## Где

- `apps/server/src/api/operator/` — guard и декоратор ролей.
- `apps/server/src/domain/operators/` — список заблокированных.

## Требования из плана

- Оператор (браузер): токен оператора (JWT, 15 мин), хранится в памяти вкладки, действия оператора в рамках роли.
- Заблокированный оператор (`disabled_at`) сразу попадает в список блокировок: запросы отклоняются.
- Список заблокированных операторов хранится в памяти каждой реплики; проверка токена — без обращения к БД.

## Документация

- https://docs.nestjs.com/guards
- https://docs.nestjs.com/security/authorization

## Критерии приёмки

- Без токена — 401.
- `operator` не выполняет действие `supervisor` (403), `supervisor` — выполняет.
- Токен с подменённым `alg` или чужим `kid` — 401.
- Токен посетителя (`aud` `visitor`) на операторском маршруте — 401.
- Заблокированный оператор с действующим токеном — 401.

## Чего не делать

- Не делать синхронизацию блокировок между репликами — это эпик кэша.
