# EPIC-14 / TASK-2. Сброс кэша на всех репликах через Redis

Исполнитель: sonnet
Зависит от: TASK-1
Ветка: feature/EPIC-14

## Что сделать

1. Подключить к режимам `api` и `worker` транспорт Redis из `@nestjs/microservices` как гибридное приложение (`connectMicroservice`).
2. Событие `cache.invalidate` с ключами, которые нужно удалить. Реплика, где произошло изменение, публикует его; каждая реплика, включая отправителя, удаляет записи у себя.
3. Отзыв ключа, изменение доменов и настроек проекта публикуют `cache.invalidate`.
4. Если событие потерялось, запись всё равно истечёт через 60 секунд.

## Где

- `apps/server/src/infra/cache/`.
- `apps/server/src/main.ts` или модули запуска режимов — подключение микросервиса.

## Требования из плана

- Кэш — `@nestjs/cache-manager` с хранилищем в памяти. При изменении кэш сбрасывается на всех репликах через Redis: событие `cache.invalidate` уходит через транспорт Redis из `@nestjs/microservices` (pub/sub), и каждая реплика удаляет запись у себя. Если событие потеряется, запись истечёт через 60 секунд.

## Критерии приёмки

- E2e на двух экземплярах приложения: ключ проверен на обоих, отозван на первом — второй отклоняет его сразу, а не через 60 секунд.
- При недоступном Redis изменение на реплике всё равно сбрасывает её собственный кэш.
