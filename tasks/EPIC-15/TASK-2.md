# EPIC-15 / TASK-2. Медленные операции одной строкой warn

Исполнитель: sonnet
Зависит от: —
Ветка: feature/EPIC-15

## Что сделать

1. Переменная `SOWA_SLOW_OPERATION_MS`, по умолчанию 500.
2. Механизм замера шагов: любой код может отметить время шага (`auth`, `db`, `redis`, `queueWait`, `bot` и т. д.) в контексте текущей операции через `nestjs-cls`. Время одного шага за операцию суммируется.
3. Если HTTP-запрос выполнялся дольше порога — одна строка `warn` с общим временем, маршрутом (шаблоном) и разбивкой по шагам. Быстрый запрос такой строки не пишет.
4. Механизм должен подходить и для фоновых задач: позже его подключат задачи очередей в `worker`.
5. Подключить замер шага `auth` в существующих guards и шага `db` — там, где это делается в одном месте без правок каждого репозитория (например, через логгер запросов TypeORM). Если общего места нет — описать в отчёте.

## Где

- `apps/server/src/telemetry/`.
- `apps/server/src/infra/config/`, `apps/server/.env.example`.

## Требования из плана

- Медленные операции: если запрос или задача выполнялись дольше `SOWA_SLOW_OPERATION_MS` (по умолчанию 500 мс), пишется одна строка уровня `warn` с разбивкой времени по шагам (`auth`, `db`, `redis`, `queueWait`, `bot` и т. д.). Быстрые операции такую строку не пишут.

## Документация

- https://docs.nestjs.com/interceptors
- https://papooch.github.io/nestjs-cls/

## Критерии приёмки

- Тестовый запрос, который выполняется дольше порога, даёт ровно одну строку `warn` с разбивкой по шагам.
- Быстрый запрос не даёт ни одной такой строки.
- Два параллельных запроса не смешивают свои шаги.

## Чего не делать
