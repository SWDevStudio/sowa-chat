# EPIC-16 / TASK-1. Лимиты запросов со счётчиками в Redis

Исполнитель: sonnet
Зависит от: —
Ветка: feature/EPIC-16

## Что сделать

1. Подключить `@nestjs/throttler` с хранилищем `@nest-lab/throttler-storage-redis` на клиенте Redis приложения: счётчики общие для всех реплик.
2. Глобального лимита на все маршруты нет: лимиты назначаются конкретным маршрутам по имени (именованные лимиты throttler). Первые лимиты добавит TASK-3.
3. Превышение — 429 `rateLimited` в едином формате ошибок и заголовок `Retry-After` в секундах.
4. Ключ счётчика задаётся лимитом: по IP, по посетителю или по токену. Способ выбрать ключ — в одном месте.

## Где

- `apps/server/src/infra/rate-limit/` — модуль.

## Требования из плана

- Лимиты запросов: `@nestjs/throttler`, счётчики в Redis через `@nest-lab/throttler-storage-redis`.
- Порядок такой: сначала замедление (`429` с `Retry-After`), при продолжении — временная блокировка (блокировку делает эпик защиты от спама).
- Посетитель видит понятную ошибку, пороги ему не раскрываются.
- Счётчики живут только в Redis с истечением срока, IP в БД не попадает.

## Документация

- https://docs.nestjs.com/security/rate-limiting
- https://github.com/jmcdo29/nest-lab/tree/main/packages/throttler-storage-redis

## Критерии приёмки

- Тестовый маршрут с лимитом 3 в минуту: четвёртый запрос — 429 с `Retry-After`.
- Лимит общий для двух экземпляров приложения: запросы к разным экземплярам суммируются.
- Маршрут без лимита не ограничивается.

## Чего не делать

- Не назначать лимиты реальным маршрутам — это TASK-3.
