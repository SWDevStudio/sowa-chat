# EPIC-16 / TASK-2. Настоящий IP только от доверенных прокси

Исполнитель: sonnet
Зависит от: —
Ветка: feature/EPIC-16

## Что сделать

1. Переменная `SOWA_TRUSTED_PROXIES` — список адресов и подсетей CIDR через запятую. По умолчанию пусто.
2. IP клиента берётся из `X-Forwarded-For` только если запрос пришёл от адреса из этого списка. Иначе — адрес TCP-соединения. Это настройка `trust proxy` в Express на всех четырёх серверах.
3. Код получает IP клиента в одном месте (например, `req.ip`) и нигде не разбирает заголовок сам.
4. Если `SOWA_TRUSTED_PROXIES` пуст, а запрос пришёл с `X-Forwarded-For`, — предупреждение в лог один раз за запуск: все посетители выглядят как один IP, и лимиты срабатывают на всех сразу. Проверка регистрируется в общем списке проверок окружения (EPIC-11/TASK-6); в `doctor` её нет, она видна только на живом трафике.

## Где

- `apps/server/src/main.ts` или модуль запуска режима `api`.
- `apps/server/src/infra/config/`, `apps/server/.env.example`.

## Требования из плана

- Настоящий IP клиента берётся из `X-Forwarded-For` только от доверенных прокси (`SOWA_TRUSTED_PROXIES`): иначе заголовок можно подделать и обойти лимиты запросов.
- Сервер не сохраняет IP: он используется только в моменте, для лимитов.
- Запросы приходят от прокси с `X-Forwarded-For`, а `SOWA_TRUSTED_PROXIES` пуст — предупреждение один раз за запуск.

## Документация

- https://expressjs.com/en/guide/behind-proxies.html

## Критерии приёмки

- Без `SOWA_TRUSTED_PROXIES` запрос с `X-Forwarded-For: 1.2.3.4` даёт IP соединения, а не `1.2.3.4`.
- С адресом тестового клиента в списке — IP `1.2.3.4`.
- Неверный CIDR в переменной — сервис не стартует.
- Без `SOWA_TRUSTED_PROXIES` два запроса с `X-Forwarded-For` дают одно предупреждение в логе, а не два.
