# EPIC-16 / TASK-4. CORS публичной и операторской зон по доменам проекта

Исполнитель: sonnet
Зависит от: —
Ветка: feature/EPIC-16

## Что сделать

CORS включается на публичном и операторском портах, у каждого свой список доменов проекта:

| Порт | Список доменов | Откуда приходят запросы |
|---|---|---|
| публичный | `projects.allowed_origins` | сайт с виджетом посетителя |
| операторский | `projects.operator_allowed_origins` | админка с операторами |

На внутреннем и служебном портах CORS нет: туда ходят бекенды, а не браузеры.

1. Preflight-запрос (`OPTIONS`) ещё не знает проекта, поэтому `Origin` проверяется по объединённому списку доменов всех проектов для этого порта. Список берётся из кэша и сбрасывается при изменении доменов.
2. Запрос с данными проверяется строже: `Origin` должен входить в список именно того проекта, к которому относится запрос.
   - Публичная зона: для `POST /v1/visitor/session` — проект по `publicKey`, для остальных — проект из токена посетителя.
   - Операторская зона: проект из токена оператора.
   - Чужой `Origin` — 403 `forbidden`.
3. Запрос без заголовка `Origin` (не из браузера) пропускается CORS-проверкой; его защищают токены и лимиты.
4. Ответ на чужой `Origin` не содержит CORS-заголовков.
5. Разрешены только нужные методы и заголовки (`Authorization`, `Content-Type`, `X-Request-Id`); cookie не используются, `Access-Control-Allow-Credentials` не ставится.
6. Домен из списка сайта не проходит на операторском порту, и наоборот.

## Где

- `apps/server/src/api/visitor/` и `apps/server/src/api/operator/` — проверка `Origin` по проекту.
- Модуль запуска режима `api` — CORS на публичном и операторском серверах.

## Требования из плана

- Allowed origins на проект, два отдельных списка: `allowed_origins` — домены сайта для публичной зоны, `operator_allowed_origins` — домены админки для операторской зоны. Домен сайта не получает CORS-доступа к операторскому API, а домен админки — к публичному.
- В development — `localhost`, в production — пусто: браузеры не пустят, пока домен не указан явно.
- Сайт (браузер) с publicKey может только создать сессию посетителя; защищён allowed origins и rate limit.
- Авторизация только через заголовок `Authorization`; cookie не используются, поэтому CSRF невозможен.

## Критерии приёмки

- Preflight с домена сайта на публичном порту получает CORS-заголовки, с чужого — нет.
- Preflight с домена админки на операторском порту получает CORS-заголовки, а с домена сайта — нет.
- Создание сессии с `Origin` другого проекта — 403.
- Запрос оператора с `Origin` админки другого проекта — 403.
- На внутреннем и служебном портах CORS-заголовков нет.
- После `origin:add` или `operator-origin:add` новый домен проходит без перезапуска (на других репликах — не позже чем через 60 секунд).

## Чего не делать

- Не проверять `Origin` для WebSocket — это эпик WebSocket.
