# EPIC-17 / TASK-5. Закрытые порты и несколько реплик api

Исполнитель: sonnet
Зависит от: TASK-2
Ветка: feature/EPIC-17

## Что сделать

1. Проверить и при необходимости поправить compose так, чтобы:
   - наружу был опубликован только порт `edge`;
   - операторский и внутренний порты `api` были доступны только внутри сети compose;
   - у `api` не было `container_name` и опубликованных портов, мешающих масштабированию.
2. `docker compose up --scale api=3` поднимает три реплики, и `edge` распределяет запросы между ними (nginx разрешает имя `api` в адреса всех реплик; при необходимости — `resolver` Docker и переменная в `proxy_pass`, чтобы новые реплики подхватывались).
3. Как открыть операторский и внутренний порты наружу явной правкой — пример в `.env.example` или в отдельном override-файле.

## Где

- `deploy/compose/docker-compose.yml`, `deploy/compose/nginx.conf`.

## Требования из плана

- В docker-compose наружу публикуется только публичный порт `edge`. Операторский и внутренний порты доступны только внутри сети compose или на `127.0.0.1`; открыть их можно явной правкой.
- Если DevOps по ошибке опубликует наружу «порт сервиса», это будет публичный порт.
- Проверка: docker-compose с `--scale api=3` за nginx.

## Документация

- https://docs.docker.com/reference/cli/docker/compose/up/
- https://nginx.org/en/docs/http/ngx_http_upstream_module.html

## Критерии приёмки

- `--scale api=3` поднимает три реплики без конфликтов портов.
- Запросы через `edge` доходят до разных реплик (видно по логам).
- С хоста недоступны порты 8081, 8082 и 9090 реплик.

## Чего не делать

- Не делать e2e-тест с убийством реплики — это эпик нескольких реплик.
