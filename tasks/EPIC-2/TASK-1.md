## Что сделать

Сделать модуль конфигурации сервера на `@nestjs/config`. Он один читает переменные окружения, проверяет их Zod-схемой при старте и отдаёт остальному коду типизированные объекты без префиксов.

1. Zod-схема переменных окружения. С неверным или неполным `.env` сервис не стартует, а в ошибке называет переменную и причину.
2. Конфиг разбит на группы через `registerAs`, код получает группу через `ConfigType` (инъекция типизированного объекта), а не через `configService.get('строка')`.
3. Переменные, которые нужны на этом этапе:

   | Группа | Переменная | По умолчанию | Что это |
   |---|---|---|---|
   | app | `SOWA_ENV` | `production` | `development` или `production` |
   | app | `NODE_ENV` | — | стандартная, читается как есть |
   | ports | `SOWA_PUBLIC_PORT` | `8080` | публичная зона |
   | ports | `SOWA_OPERATOR_PORT` | `8081` | операторская зона |
   | ports | `SOWA_INTERNAL_PORT` | `8082` | внутренняя зона |
   | ports | `SOWA_MANAGEMENT_PORT` | `9090` | служебная зона |
   | database | `DATABASE_URL` | — | обязательна |
   | redis | `REDIS_URL` | — | обязательна |
   | s3 | `SOWA_S3_ENDPOINT`, `SOWA_S3_ACCESS_KEY`, `SOWA_S3_SECRET_KEY`, `SOWA_S3_BUCKET` | — | уже есть в `.env.example` |

   Остальные переменные добавляют задачи, которым они нужны: каждая дописывает свою группу или поля по тому же образцу.
4. Обновить `apps/server/.env.example`.

## Где

- `apps/server/src/infra/config/` — новый модуль.
- `apps/server/.env.example`.

## Требования из плана

- `.env` проверяется через Zod при старте: ошибка в конфиге видна сразу, а не на первом запросе.
- Имена переменных — внешний контракт с DevOps. Стандартные — без префикса (`DATABASE_URL`, `REDIS_URL`, `NODE_ENV`, `OTEL_*`), все собственные — с префиксом `SOWA_`, в UPPER_SNAKE_CASE. В коде — типизированный конфиг без префиксов и в camelCase: `config.ports.public`, а не `SOWA_PUBLIC_PORT`.
- Переменные окружения читает только модуль конфигурации. `process.env` в остальном коде запрещён.
- Порты — целые числа от 1 до 65535, разные у всех зон.
- В `apps/server` barrel-файлы не используются: импорт напрямую из файлов.

## Критерии приёмки

- Без `DATABASE_URL` сервис не стартует, в выводе есть имя переменной.
- `SOWA_ENV=staging` и `SOWA_PUBLIC_PORT=abc` отклоняются с понятной ошибкой.
- Два одинаковых порта зон отклоняются.
- Без необязательных переменных подставляются значения по умолчанию.
- Поиск `process.env` по `apps/server/src` находит только модуль конфигурации.
- Unit-тесты схемы.
