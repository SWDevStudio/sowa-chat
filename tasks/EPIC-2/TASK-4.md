# EPIC-2 / TASK-4. Корректное завершение по SIGTERM

Исполнитель: sonnet
Зависит от: TASK-3
Ветка: feature/EPIC-2

## Что сделать

По сигналу SIGTERM (и SIGINT) режимы `api` и `worker` закрывают соединения и выходят с кодом 0.

1. Включить хуки завершения Nest (`enableShutdownHooks`) во всех режимах.
2. `api` перестаёт принимать новые соединения, дожидается текущих запросов и закрывается.
3. Добавить страховочный таймаут: если остановка не уложилась в заданное время, процесс завершается с кодом 1 и пишет, что не закрылось. Значение — переменная `SOWA_SHUTDOWN_TIMEOUT_MS`, по умолчанию 30 000; добавить её в модуль конфигурации.
4. Модули, которые позже откроют соединения (БД, Redis, очереди), закрывают их в своих lifecycle-хуках. Здесь нужен только общий механизм и проверка, что он работает.

## Где

- `apps/server/src/main.ts` и корневые модули режимов.
- `apps/server/src/infra/config/` — новая переменная.

## Требования из плана

Обновление (rolling update): SIGTERM → readiness = false → пауза 5–10 с → сокеты закрываются пачками за 10–20 с → клиенты уходят на другие поды. Readiness и сокеты появятся в следующих эпиках, а сейчас нужна основа: процесс по SIGTERM завершает работу сам и без ошибок.

## Документация

- https://docs.nestjs.com/fundamentals/lifecycle-events

## Критерии приёмки

- Запущенный `api` после SIGTERM завершается с кодом 0 и без ошибок в выводе.
- Запрос, который выполнялся в момент SIGTERM, получает ответ.
- Запущенный `worker` после SIGTERM завершается с кодом 0.

## Чего не делать

- Не реализовывать readiness и закрытие сокетов пачками — это эпики служебной зоны и нескольких реплик.
