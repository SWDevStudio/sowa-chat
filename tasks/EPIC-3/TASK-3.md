# EPIC-3 / TASK-3. Скрытие секретов и персональных данных в логах

Исполнитель: sonnet
Зависит от: TASK-1
Ветка: feature/EPIC-3

## Что сделать

Настроить redact в pino, чтобы в логи не попадали токены, ключи, тексты сообщений и контакты. Скрытое значение заменяется на `[Redacted]`.

Скрывать:
- заголовки запроса `authorization`, `cookie`, `x-api-key` и заголовок ответа `set-cookie`;
- поля с токенами и ключами в любом объекте лога: `token`, `accessToken`, `refreshToken`, `publicKey`, `serverKey`, `botKey`, `secret`, `password`, `key`;
- текст сообщений и контакты: `text`, `body`, `email`, `phone`, `name`;
- данные интегратора: `context`, `visitorData`, `payload`.

Список путей держать в одном месте, чтобы его было легко пополнять.

## Где

- `apps/server/src/infra/logging/`.

## Требования из плана

- Тексты сообщений, токены, ключи и контакты в логи не пишем (redact в pino).
- IP — внутренняя системная информация: используется только в моменте для лимитов, в БД не попадает. В логах запросов IP допустим, это стандартное поле HTTP-лога.
- Действия операторов и ботов пишутся в `audit_log`, а не в логи.

## Документация

- https://getpino.io/#/docs/redaction

## Критерии приёмки

- Запрос с заголовком `Authorization: Bearer sk_test`: в логе заголовок равен `[Redacted]`, строки `sk_test` в выводе нет.
- Лог объекта `{ message: { text: "привет" }, email: "a@b.c" }` не содержит `привет` и `a@b.c`.
- Поля, которых нет в списке, логируются как есть.

## Чего не делать

- Не убирать логирование запросов целиком.
