С первой попытки упали два теста с таймаутом 5 с: первый тест файла платит за холодный импорт Nest при параллельном прогоне. Разбор (opus): виноваты тесты, не код. Исправлено задачей `review` (`describe(name, { timeout: 20_000 }, fn)`), повторный прогон: PASS.

## Ревью (opus)

Блокирующих замечаний нет. Пункты «стоит поправить» не исправлялись, потому что противоречат решениям из `decisions.md` или решению разработчика:

- `api-app.ts:15`, `zone.guard.ts:9`: guard создаётся через `new`, ревьюер предлагает `APP_GUARD` в `ZonesModule`. Решение планировщика: `useGlobalGuards`, чтобы не закрыть маршруты тестов логов.
- `zone.guard.ts:16-18`: не-HTTP контекст отклоняется. Проверку WebSocket добавит эпик WebSocket (PLAN.md §15).
- `zone-servers.ts:33-40`, `main.ts:26-27`: `IoAdapter` по умолчанию подключается к `app.getHttpServer()`, а он не слушает. Эпику WebSocket нужен адаптер, который подключается к серверам зон через `getServer(zone)`.
- `zone-servers.ts:46`: серверы закрываются только при `app.close()`. Обработка SIGTERM (`enableShutdownHooks`) отклонена разработчиком в EPIC-2 TASK-4.

Мелочи: `getServer` вызывается только из теста (нужен эпику WebSocket); `useAppLogger` повторяется в `api-app.ts` и `main.ts`; `@Zone` на `SetMetadata` со строковым ключом (причина — в `decisions.md`).
