# EPIC-5 / TASK-2. Режим migrate

Исполнитель: sonnet
Зависит от: TASK-1
Ветка: feature/EPIC-5

## Что сделать

1. Режим `migrate` применяет все непримененные миграции и завершается: код 0 при успехе, код 1 при ошибке.
2. Подключение: `SOWA_MIGRATION_DATABASE_URL`, если она задана, иначе `DATABASE_URL`. Переменная `SOWA_MIGRATION_DATABASE_URL` необязательна во всех режимах.
3. Миграции лежат в `apps/server/src/infra/database/migrations/` и попадают в сборку.
4. Скрипты в `apps/server/package.json`:
   - `migration:generate` — сгенерировать миграцию из сущностей;
   - `migration:create` — пустая миграция для ручного SQL.
5. Отдельный DataSource для CLI TypeORM, с тем же списком сущностей, что у приложения.
6. Режим `migrate` устроен так, чтобы после миграций в нём можно было выполнить следующие шаги подготовки: эпик хранилища файлов добавит создание бакета и его CORS-правил. Шаги выполняются по порядку, ошибка любого — код 1.
7. В `.env.example` `SOWA_MIGRATION_DATABASE_URL` закомментирована как необязательная. Dev-compose не меняется: один пользователь `sowa`.

## Где

- `apps/server/src/infra/database/`.
- `apps/server/package.json`, `apps/server/.env.example`.

## Требования из плана

- Приложение работает под пользователем PostgreSQL без прав суперпользователя. Достаточно одного пользователя (`DATABASE_URL`); кто хочет строже, задаёт отдельного пользователя для миграций (`SOWA_MIGRATION_DATABASE_URL`).
- Перед выкаткой один шаг — `migrate`: он применяет миграции, создаёт бакет и обновляет его CORS-правила.
- Миграции генерируются из сущностей, но каждая проверяется на ревью. GIN-индексы и `CREATE INDEX CONCURRENTLY` (миграция без транзакции) пишутся руками.
- Старые и новые поды работают одновременно, поэтому миграции только обратно совместимые (expand → contract) и запускаются отдельно до выкатки.
- Базы данных не создаются автоматически: схема — только миграциями.

## Критерии приёмки

- `node dist/main.js migrate` применяет миграции и завершается с кодом 0; повторный запуск ничего не меняет и тоже выходит с 0.
- Ошибка в миграции — код 1 и понятное сообщение.
- Без `SOWA_MIGRATION_DATABASE_URL` миграции идут по `DATABASE_URL`; с ней — по ней.

## Чего не делать

- Не создавать сущности и миграции с таблицами — это TASK-4.
- Не подключать к режиму `migrate` модули, которым нужен Redis или HTTP.
- Не добавлять init-скрипты PostgreSQL и вторых пользователей в compose.
