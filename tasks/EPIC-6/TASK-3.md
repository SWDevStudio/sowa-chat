# EPIC-6 / TASK-3. Проверки /health/live и /health/ready

Исполнитель: haiku
Зависит от: TASK-1
Ветка: feature/EPIC-6

## Что сделать

Сделать проверки здоровья на `@nestjs/terminus` в служебной зоне (порт 9090, без версии в пути).

1. `GET /health/live` — только сам процесс: отвечает 200, пока процесс жив и обрабатывает запросы. Внешние зависимости не проверяет.
2. `GET /health/ready` — PostgreSQL и Redis. Всё доступно — 200, хотя бы одно недоступно — 503 с указанием, что именно.
3. Проверка Redis — свой индикатор через `PING` клиентом из TASK-1.
4. Контроллер помечен служебной зоной (`@Zone('management')`) и `VERSION_NEUTRAL`.
5. Readiness можно перевести в «не готов» программно: при остановке реплики (SIGTERM) он должен сразу отвечать 503. Сейчас нужна только эта возможность, использовать её будет эпик нескольких реплик.

## Где

- `apps/server/src/infra/health/` — новый модуль.

## Требования из плана

- Readiness проверяет Postgres и Redis, liveness — только сам процесс. Если проверять БД в liveness, её падение перезапустит все поды.
- Служебная зона, наружу не публикуется: `/health/live`, `/health/ready`, `/metrics`, `/status`.

## Документация

- https://docs.nestjs.com/recipes/terminus

## Критерии приёмки

- При работающих PostgreSQL и Redis оба эндпоинта отвечают 200.
- При остановленном PostgreSQL `/health/ready` отвечает 503, а `/health/live` — 200.
- На публичном порту `/health/live` отвечает 404.

## Чего не делать

- Не переключать readiness по SIGTERM — это эпик нескольких реплик.
