## Что сделать

`GET /status` в служебной зоне отдаёт JSON для человека, который смотрит через `curl`:

```json
{
  "version": "0.0.1",
  "mode": "api",
  "uptimeSeconds": 1234,
  "postgres": { "status": "up" },
  "redis": { "status": "up" }
}
```

- `version` — из `package.json` сервера.
- `status` зависимостей — `up` или `down`; при `down` — краткая причина без секретов и строк подключения.
- Ответ всегда 200: это сводка, а не проверка готовности.
- Состав ответа должен легко расширяться: позже добавятся S3, открытые сокеты, длина очередей, отставание outbox, боты со сработавшим предохранителем.

## Где

- `apps/server/src/infra/health/` или отдельный модуль рядом.

## Требования из плана

- Сводка состояния: JSON на `/status` (служебный порт 9090) — версия, аптайм, открытые сокеты, длина очередей, отставание outbox, состояние PostgreSQL, Redis и S3, боты со сработавшим предохранителем. Сейчас — только версия, аптайм, PostgreSQL и Redis; S3 добавится в эпике хранилища файлов.

## Критерии приёмки

- `GET /status` на порту 9090 отвечает 200 и JSON с полями выше.
- При остановленном PostgreSQL ответ 200, а `postgres.status` = `down`.
- В ответе нет `DATABASE_URL`, `REDIS_URL` и паролей.
