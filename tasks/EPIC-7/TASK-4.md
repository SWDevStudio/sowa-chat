# EPIC-7 / TASK-4. Лимит тела 64 КБ и правило limit для страниц

Исполнитель: haiku
Зависит от: TASK-1
Ветка: feature/EPIC-7

## Что сделать

1. Тело JSON-запроса ограничено 64 КБ. Больше — 413, `payloadTooLarge`. Лимит проверяется до разбора JSON.
2. В `protocol` — общая схема параметров страницы: `limit` от 1 до 100, по умолчанию 50. Значение вне диапазона даёт 400. Схему используют все эндпоинты со списками.

## Где

- `apps/server/src/main.ts` или модуль запуска режима `api` — лимит тела.
- `packages/protocol/src/` — схема страницы, реэкспорт в `index.ts`.

## Требования из плана

- Проверка в два слоя: лимит тела запроса 64 КБ ещё до разбора JSON, затем zod-схема.
- Файлы идут мимо api (прямо в S3), поэтому большой лимит тела не нужен.
- Все списки отдаются страницами. `limit` — от 1 до 100, по умолчанию 50; значение вне диапазона даёт `400`, его отсекает схема запроса. Ограничение держит сервер: запрос с огромным `limit` можно отправить в обход SDK.

## Документация

- https://docs.nestjs.com/faq/raw-body
- https://expressjs.com/en/api.html#express.json

## Критерии приёмки

- Тело 65 КБ — 413 с `code: payloadTooLarge`; тело 63 КБ проходит.
- `?limit=0` и `?limit=101` — 400; без `limit` подставляется 50.

## Чего не делать

- Не делать курсоры страниц — у каждого списка они свои.
