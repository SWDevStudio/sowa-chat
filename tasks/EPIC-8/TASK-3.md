# EPIC-8 / TASK-3. Подписчик журнала аудита

Исполнитель: sonnet
Зависит от: TASK-1, TASK-2
Ветка: feature/EPIC-8

## Что сделать

Подписчик на внутренней шине, который записывает в `audit_log` доменные события, нужные для аудита.

1. Какие события попадают в журнал — явный список в одном месте. Событие, которого нет в списке, в журнал не пишется.
2. Для каждого события из списка задано, как получить `actorKind`, `actorId`, `action`, `targetKind`, `targetId` и `data`.
3. В `data` попадают только ID и неличные поля (например, число удалённых сообщений). Имена, email, телефоны, тексты, IP, токены и ключи — никогда.
4. Ошибка записи в журнал логируется и не роняет действие, которое её вызвало.

## Где

- `apps/server/src/domain/audit/` — подписчик.

## Требования из плана

- `audit_log` — подписчик внутренней шины, домен не импортирует подписчиков.
- У каждого действия есть автор: журнал показывает, кто ответил и кто закрыл диалог.
- Создание и отзыв ключей, удаления, блокировки пишутся в журнал аудита без персональных данных.
- IP — внутренняя системная информация, в БД не попадает.

## Документация

- https://docs.nestjs.com/techniques/events

## Критерии приёмки

- Тестовое событие из списка создаёт строку в `audit_log` с правильными полями.
- Событие не из списка строку не создаёт.
- Unit-тест подписчика: персональные поля из данных события в `data` не попадают.
- Проверка слоёв проходит: домен не импортирует подписчика.

## Чего не делать

- Не добавлять в список реальные события — их добавляют задачи, которые эти события создают (ключи, CLI и т. д.).
